## 钩子(0-8 秒)

你是不是还在研究,怎么把给 AI 的提示词写得更漂亮?
我得说个有点扎心的消息:写出 Claude Code 的那个人,已经不写提示词了。
他说——"我的工作,是写循环。"

## 第一段 · 你在卷提示词,顶尖的人换了赛道

这句话来自 Boris Cherny,Anthropic 里负责 Claude Code 的人。
原话是:"我不再 prompt Claude 了。我写循环,循环替我干活。"
紧接着,Google 的工程师 Addy Osmani 给这件事起了个名字,叫 loop engineering,循环工程。
你可能想,这不就是换个说法?还真不是。
loop engineering 是把跟 AI 打交道这件事整个翻过来:你不再一句句指挥它,你去设计一条循环,让循环替你不停地指挥它、还自己验收。
说人话,你的角色从"操作机器的人",变成"设计那条机器自己跑的产线的人"。
这不是把老路往前走一步,是换了一根轴。

## 第二段 · 四级台阶:你操心的东西一直在往上挪

在说怎么写循环之前,先把这两年的路捋一遍,你就知道它新在哪。
这两年我们其实爬了四级台阶,每上一级,你操心的东西就往上挪一层,人也离机器更远一步。
第一级,prompt engineering。你抠的是那一句话——怎么把问题问清楚,让它一次答好。
第二级,context engineering。你不只管那句话了,你开始管它每一轮能看到什么——给它对的资料、对的历史,别让没用的东西占了它有限的注意力。
第三级,harness engineering。你管的是它整个工作台——配什么工具、关在什么沙箱、结果怎么反馈给它,让它单次能跑稳。这一级我之前专门做过一期。
第四级,就是现在的 loop engineering。你管的不再是某一次,而是整条循环本身——它什么时候自己开工、干完谁来验、状态怎么存下来明天接着干。
你看这条线:抠一句话,到布置桌面,到搭工作台,到设计整条产线——你一步步从"亲自操作的人",退成了"设计系统的人"。前三级你都还得在场;到第四级,你可以下班了,它自己转。
所以 loop 是踩在 harness 肩膀上的:工作台解决"一次干得好",循环解决"不用你喊,它自己一轮一轮干下去"。

## 第三段 · 给 agent 招一个会自己上班的"数字员工"

那"写循环"到底写什么?听着玄,其实特别具体。
你把它想成:你给 AI 招了个会自己上班的"数字员工",而你的活是设计它的岗位和班子。按 Osmani 原文的分法,是五样零件,外加单独的一本交接日记。先说五样零件——
一,一个闹钟:定时自己去发现有什么活要干,而不是等你开口。
二,一个独立工位:能同时开好几摊,互相不打架。
三,一本岗位手册:把项目怎么干、规矩是什么,写下来交给它。
四,一部外线电话:够得到外面的工具和数据。
五,也是灵魂——一个专门给它挑错的同事。
这五样之外,还有单独的第六样,一本交接日记:今天干到哪、卡在哪记下来,明天自己翻开接着干。它为什么要单拎出来?因为模型每跑完一轮就把上一轮忘得差不多了,状态只能写在它脑子外面、写在硬盘上,它下一轮才接得上。
重点说第五个。为什么是灵魂?因为让 AI 给自己打分,它会手软,总觉得自己干得还行。
所以靠谱的循环,把"写的"和"检查的"拆成两个角色:一个负责干,另一个换一套标准专挑毛病。
Anthropic 做长跑 agent 时反复强调:写的和验的,必须分开。
有了这个挑错的同事,循环才敢在没人盯着时,自己跑下去。

## 第四段 · 举个最小的例子,把这几样串起来

光说原理还是飘,给你看一个最小的循环长什么样。
假设你就想让它帮你盯着,别让项目的测试一直挂着。
一条最小的循环是这样:每天早上九点,闹钟一响,它自己去看一眼——昨天有没有测试挂了?这是闹钟。
挂了,它开一个独立工位,把出问题的地方拉过来改,绝不碰你正用着的主干。这是工位。
改完,它不自己拍胸脯说"我好了",而是叫上那个专门挑错的同事,拿项目的测试跑一遍,验过才算数。这是挑错的同事。
验过了,它给你提一个待审的修改,等你睡醒瞄一眼;没验过,它把"卡在哪"记进交接日记,明天接着试。这是交接日记。
你看,从发现、动手、自检、到交接,整整一圈,没用你插一句话。你做的,只是设计了这一圈。

## 第五段 · 那五样,在 Claude Code 和 Codex 里分别长什么样

这段单拉出来讲,因为它是 Osmani 那篇最实在的地方:同样五样零件,Claude Code 和 Codex 几乎是镜像的,名字差一点,能力一模一样。先说一句让你松口气的,这些基本不用你自己写脚本,一年前你想要个循环得自己堆一大坨脚本天天维护,现在零件直接做进产品里了。下面带你认一遍,同样五样,两个工具里分别叫什么。
第一样,闹钟,也就是 Automation。Codex 里是一个自动化标签页,挑项目、写提示、定多久跑一次、选在哪跑,有结果的进收件箱,没结果的自动归档。Claude Code 这边是定时任务、循环命令,加上 hooks 和 GitHub Actions。一个意思,定义一个自动任务,给它节奏,结果送到你面前。
第二样,工位,Worktree。Codex 每个线程内建一个。Claude Code 用 git worktree,给每个子代理单独开一份干净的副本,用完自动清,谁也不碰谁。
第三样,手册,Skill。这俩完全一样,一个文件夹里放一个 SKILL.md,装着指令和规矩,两边都能按名字调,或者任务一匹配就自动用上。
第四样,外线,Connector。两边都是 MCP,你给一个工具写的连接器,搬到另一个里通常直接能用。
第五样,挑错的同事,Sub-agent。Codex 把子代理写成它自己 agents 目录里的配置文件,Claude Code 也放在 agents 目录里,还能让几个子代理组队,互相传活。
还有一个目标命令也是对称的,两边都有,让 agent 一直干到你写的条件真的成立,而且收尾是另一个模型来判完没完,写的和判的分开。
Osmani 最后点了句关键的,你一旦发现两边形状是一样的,就不再纠结用哪个工具了,你设计的是一条循环,它在 Codex 能跑,搬到 Claude Code 照样跑。这才是 loop engineering 真正的底气,它不绑死在哪一个工具上。

## 第六段 · 诚实补丁,以及普通人怎么抄

按规矩打个诚实补丁,泼几句冷水。
第一,有前提:它适合那些"对错能自动验"的活,比如代码能跑测试。要是一件事你自己都说不清什么叫"做对了",扔进循环,只会让它更快、更不知疲倦地错下去。
第二,成本会飘。一个没人盯的循环,也是一个没人盯、默默犯错、默默烧钱的循环。
第三,最容易被忽略也最坑——Osmani 自己管它叫"理解债"。系统开始 ship 一堆你从没读过的代码,你是快了,可你对自己的东西越来越不懂了。
同一条循环,两个人用,能跑出相反的结局:一个在他真懂的地方加速,另一个在用循环逃避"搞懂"。
那小团队、个人,今天能抄什么?别一上来就搭全自动的庞然大物。就从刚才那个最小例子开始:一个定时任务,加一个专门挑错的子代理。就这两样,你已经拿到大半好处,花的只是零头。
这一期想给你留下的就一句话:
AI 时代真正的杠杆,不在你多会说那句漂亮话,在你会不会设计一条——不用你盯着、还会自己挑错的循环。
