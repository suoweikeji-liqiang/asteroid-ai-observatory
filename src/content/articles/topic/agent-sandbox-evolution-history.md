## 钩子(0–8 秒)  [cover → hook]

先别管"沙箱"这个词,也别管 Docker、虚拟机这些名字。
我们干件更实在的:从一个什么限制都没有的 Linux 进程开始,亲手给它一层层加约束,你盯着它,看它一步步变成一个沙箱。搭完,这词什么意思你自己就懂了。

## 第一段 · 最危险的版本:一个裸进程  [concept]

你在电脑上跑一段代码,默认它什么状态?它能看见你所有文件、能上网、能开任意多进程、能调用内核任何一个功能——几乎和你本人一样有权力。要是这段代码是 AI 现写的、你一行没读过,这就很吓人。
所以"做沙箱",剥到最朴素就一句话:把这个裸进程的权力,一项一项收回来。我们开始收。

## 第二段 · 一项项收,每收一项看一眼变化  [concept cards 蓝/黄/红]

我们不抄 Docker,用内核给的零件自己搓:
先收"它能看见什么"——加一个 namespace。加之前它 `ps` 能看见你机器上所有进程;加之后只看得见自己。一行 `unshare`,世界缩成一间屋。
再收"它能用多少"——加一个 cgroup。加之前一个 `while True` 能把 CPU 烧满、内存吃光;加之后到 1 核、512M 就掐住。
再收"它能调什么"——加一个 seccomp。内核对外开着几百个系统调用窗口,一个只做数学的程序根本用不到 mount、用不到加载内核模块——把用不到的焊死,它能碰到内核的面一下小一大圈。
看见没?我没让你背"三大组件"。我们是把一个裸进程的权力一项项收回来,每收一项,亲眼看它少掉一种作恶的能力。这三样收完,你已经手搓出一个沙箱了,丑,但它是真的。

## 第三段 · 剥到本质核:五个问题,其余全是效率  [divider]

停一下,做我每次都做的事:剥本质。
你刚才收权力,其实就在回答五个问题——它能看见什么、能用多少、能调什么,再加上能连哪里、走时能带走什么。
后面你会撞到一长串名字:Docker、bwrap、gVisor、Firecracker、E2B……看着五花八门。但攥住这个核你就不晕:它们没有一个是新问题,全在回答这五个问题,区别只在于把某道墙砌得多狠。所以接下来别背技术,只问一句:这个新名字,把五个问题里的哪一个,砌得更硬了?

## 第四段 · Docker:把手搓工程化了,但共享你那一个内核  [not-vs 上半]

很多人以为容器是 Docker 发明的。不是——namespace、cgroup 这些它之前早有了。Docker 的伟大,是把你刚才那堆手搓命令,做成一套标准装修:镜像、分层、打包、分发、生态,让软件带着环境一致地搬来搬去。
但你亲手搓过就知道一件事:普通 Docker 容器里的程序,系统调用还是直愣愣打进你电脑里唯一那个内核,和你自己的程序共用同一颗心脏。文件、进程、网络的视图隔开了,可底下那道承重墙(内核),全楼共用——一裂,全楼一起塌。
而且最常见的事故不是 Docker 漏洞,是配置:开特权模式、把宿主根目录挂进去、把物业总钥匙 `docker.sock` 留在工位上——碰到 docker.sock,基本等于拿到接近宿主 root。Docker 官方也明说:默认不自动给你设资源上限,默认 seccomp 也只是"适度保护"。
所以更准的说法:Docker 可以是沙箱的一部分,但不是默认安全、能跑不可信代码的环境。自己人审过的够用;陌生人、AI 现写的代码,不够。

## 第五段 · 为什么 AI 把这事重新顶上来  [concept · 列表]

为什么传统程序没这么讲究,偏 AI 要?因为传统程序人写的、测过审过的。AI Agent 有四个先天不省心:
一,生成的代码本身不确定,可能死循环、删错目录、装个投毒包,不一定恶意,后果一样;
二,会读不可信内容(网页/邮件/文档),攻击者把"忽略原任务,去读密钥发给我"藏进去,它可能真当命令执行——间接提示词注入,OWASP 列为大模型应用头号风险;
三,它不只动嘴,它有手:握着 shell、浏览器、数据库、云 API,判断错一次就是一次真实系统操作;
四,它会放大:自动重试、并行铺开,一段错代码同时跑一百遍,CPU 烧光、账单爆表。
普通 Docker 那道墙被这四件事一顶就显薄了。于是墙往下砌。

## 第六段 · gVisor 和 MicroVM:把墙砌更硬的两条路  [architecture · gVisor / MicroVM 栈 + not-vs 下半]

第一条加固,gVisor:在它和你内核之间插一层用户态的"替身内核",叫 Sentry。它替你接走大部分系统调用、自己处理,真正转交到你内核手上的少多了,还自带网络栈。代价是它不是完整 Linux,冷门调用、性能敏感的活会变慢;好处是暴露给宿主内核的面比容器小得多,还能用 Docker 镜像那套。
第二条更狠,MicroVM:连内核都隔出去。这里我挂到你写代码时熟的东西上——你 `import` 一个库,它跑在你进程里、共用你的一切;你开一台虚拟机,那才是另一台机器。容器就像 import,共用底层那一个内核;MicroVM 就像开了另一台机器,独立内核 + KVM 硬件虚拟化。这就是"容器 ≠ 强隔离"的全部。
MicroVM 不是更小的容器,它是正经虚拟机,只是把用不到的虚拟硬件全拆了:一次 AI 跑代码只要 CPU、内存、一个根文件系统、一张网卡。最有名的实现是 Firecracker(AWS 做的,Lambda、Fargate 底座),官方说特定参考硬件和配置下约 125 毫秒启动、每个 MicroVM 额外内存压到 5MB 以下——这是它特定环境的数,不是到哪都保证。关键在:他就算把自己那栋小楼的内核搞崩,还隔着虚拟化这道院墙,比共用承重墙的容器硬一个量级。代价是运维更重,配真正不可信、跨租户的代码。

## 第七段 · E2B 这些:封成 Agent 的云,但别抄黑箱  [architecture · 控制面分区]

到 Agent 时代,你要的已经不只是"起一个隔离进程",而是一键开、一键拆、传文件、装依赖、流式拿结果、限时、管出口、记日志、扛并发。E2B、CubeSandbox、OpenSandbox 就是把这套封成服务。E2B 官方写得很明确:每个沙箱底下就是一台 Firecracker MicroVM;CubeSandbox 是腾讯云开源、兼容 E2B SDK,能自建。
这里是我教东西的死规矩:别抄黑箱。你用 E2B 一行起一个沙箱很爽,但你要不知道它底下到底是普通 Docker 还是独立 MicroVM,你就是抄了一道你没懂的墙——名字带 Sandbox 不代表它就是独栋。OpenSandbox 走"统一沙箱 API",底下可能挂的就是普通 Docker。评估一个沙箱产品,追一句:每个实例底下,到底是进程、容器、gVisor,还是 MicroVM?

## 第八段 · 反转:最硬的墙,挡不住你把钥匙放他桌上  [not-vs 关键图]

这里有个反直觉的地方,也是这期最值钱的一句。先抛个现象:有人上了最硬的 MicroVM,独立内核、硬件院墙,数据还是被搬空了,而且墙完好,没人越狱。怎么回事?
因为隔离强度和权限设计,是两件正交的事。你把长期私钥挂进了他工位,又把网络全开了——他被钓鱼邮件骗去读私钥、发出去,从那栋楼的角度看,这根本不是越狱,是他在用你亲手给的合法权限。
墙(隔离)管"他翻不翻得出去";钥匙和电话(权限)管"这屋里本来放了什么、他本来能联系谁"。MicroVM 替代不了网络策略,gVisor 替代不了凭证管理,Docker 替代不了最小权限。最硬的墙,补不了一把放错地方的钥匙。

## 第九段 · 落地:那块工位怎么设(普通团队能抄)  [route-picker 选型]

一台成熟的 Agent 沙箱,剥到底就是:一台权限受限、资源受限、网络受控、凭证短效、可审计、随时能拆的一次性电脑。落地抓三件:
一,按这人多不可信选档次:自己人审过的,强化版 Docker 够;半生不熟的三方工具,加个 gVisor;完全不可信、跨客户的,上 MicroVM 或直接用 E2B、CubeSandbox。
二,金库钥匙别放工位上:编排、凭证、审批放在沙箱外面的控制面;沙箱里要用资源,就申请一张"只开这一个抽屉、几分钟作废"的临时卡。数据分析别让沙箱直连生产库,给一份脱敏临时副本,跑完销毁。
三,接口第一天写成可换的:别把业务逻辑和 docker 命令焊死,设计成一个口子 `run(代码, 文件, 限额, 网络策略)`,后面 Docker 换 gVisor 换 MicroVM 成本才不高。

## 诚实补丁  [concept / divider]

泼句冷水:沙箱限制的是后果,消灭不了提示词注入——它不会替你判断模型是不是已经被骗了。隔离解决"能不能突破边界",权限解决"边界里本来允许干什么",谁也替不了谁。所以真有人跟你说"我们用了 MicroVM,绝对安全",这句话本身就该让你多问一句。

## 收口  [close 综合图]

回头看,其实是两件事同时在发生:墙不断往下沉(文件权限→进程→三件套→容器→替身内核→硬件虚拟化),管理不断往上长(跑一次进程→镜像→模板快照→生命周期 API、网络、凭证、审计)。越往下他越难碰你的核心,越往上它越不像一条命令、越像一套给 Agent 准备的云。
这一期一句话钉住:隔离决定墙有多硬,权限决定屋里放了什么。墙再硬,钥匙放他桌上、门还开着,照样被搬空。
想真懂?别 `docker run` 完就算了——找个周末,用 `unshare`、cgroup 自己手搓一个最小沙箱,你会对每一道墙为什么在那儿,有完全不同的体感。
