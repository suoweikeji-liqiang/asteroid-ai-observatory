打开 Figma 的官方 AI 页面，会看到一长串"帮你更快开始设计、生成内容、保持工作流连续"的能力。

打开 Adobe 在 2026 年 4 月发布的官方公告，会看到 Firefly AI Assistant 已经能跨整个 Creative Cloud 编排多步骤工作流——你只需要描述目标，系统帮你执行。

打开任何招聘网站搜 UI 设计师，"熟悉 AI 设计工具"这一行，越来越常见。这些都不是预测，是你自己点开就能看到的事实。

所以问题来了——老板想知道：AI 都能生成页面、图标、Banner、原型，UI 岗位还值钱吗？UI 自己也想知道：我以前靠 Figma 和切图吃饭，现在 AI 一句话就能生成方案，我以后靠什么立足？我今天的判断是一句话：AI 替代的是画页面的动作，不是设计体验的判断。如果 UI 还把自己定位成画图的人，这个岗位的护城河确实会变薄。但如果能升级成 AI 交互设计、原型验证、和设计资产建设者，反而进入了一个稀缺窗口期。

我们不做鸡汤式判断。设计工具里那一类纯执行动作，会被 AI 大量压缩，这是看得见的趋势。Figma 的 AI 现在可以帮你快速生成多版视觉风格、补全图标、改写文案、整理图层。Adobe Firefly 已经能在 Photoshop、Illustrator、Express 之间帮你串起工作流。Cursor、v0、Lovable、Bolt.new 这一类新工具，可以直接从一句描述生成可运行的前端页面。你打开任意一个主流设计工具的更新日志，看过去一年，AI 功能都被推到了核心位置——这不是某一家在试水，是整个行业一起在变。

所以这一段我必须诚实说一句：如果一个 UI 的主要价值，只是把别人想好的东西画出来，那这个护城河一定会变薄。我说得再具体一点——只会切图、只会出图标插画、只会做营销 Banner、不参与产品判断的 UI，这一类岗位三年内会被压缩到接近消失。这不是焦虑，是行业边界被技术重画了。

但 AI 会画页面，不代表它懂体验。AI 不会天然知道：用户为什么不相信这个结论？哪些信息应该先展示？哪些操作必须人工确认？什么内容对管理者有价值？什么内容对一线员工有价值？一个复杂系统怎样让普通用户上手？AI 的建议怎样表达，才不吓人、不误导、不越权？一个产品怎样从"能用"变成"愿意用"？这些问题，才是设计真正有价值的地方。

所以我有一个判断——AI 时代最重要的界面，不是按钮，而是信任。用户能不能理解 AI 的结论？能不能看到依据？能不能追问？能不能纠错？关键动作能不能保持人工确认？这些问题不在画图工具的能力范围内，必须有人想清楚。这件事就是 UI/UX 在 AI 时代要承担的新责任。

接下来我把升级路线拆成五条。但这五条重要性差距很大，我会按这个差距分配篇幅——最强的多讲，弱的一笔带过。不要把它们当成同等并列。我心里的排序是这样：路线一和路线二是真正的稀缺窗口，路线三是基本功，路线四是组织能力，路线五更像顺手做的事。路线一（重头戏）：从界面设计，升级为 AI 交互设计。这是我认为最有红利期的方向，原因很简单——大多数公司还没意识到 AI 产品需要不一样的交互设计。传统产品的交互逻辑很清楚：用户点按钮，系统执行。AI 产品完全不是这样：系统会主动判断、建议、解释、生成，甚至主动发起任务。这就要求 UI 重新设计很多东西：AI 结论怎么展示；AI 依据怎么展开，让用户敢追问；AI 不确定的时候怎么表达，不能假装百分之百肯定；用户怎么纠错；哪些动作必须人工确认；AI 建议怎样进入用户真实的工作流，而不是只停留在对话框里。举一个具体的设计要求——如果 AI 说："这个项目有异常风险。"页面不能只显示一句话。它要同时给出：异常是什么、依据是什么、影响是什么、建议做什么、需要谁确认、确认后会发生什么。这一整套表达逻辑，叫做 AI 结论的可理解、可追问、可确认、可纠错。这件事不是普通美化能解决的，也不是产品经理能一个人定义的，必须设计师深度参与。我说得直白一点——如果你是 UI 想转型，这条路是我会优先选的方向。因为这件事必须有人做，但行业里能做的人非常少；大多数 AI 产品现在还停留在硬塞个聊天框的阶段，等他们想清楚需要专门的 AI 交互设计，那时候已经晚了。

路线二（次重头）：从接需求，升级为原型验证负责人。第二条同样有红利期，但和路线一是不同方向。AI 时代很多产品想法听起来都不错：AI 助手、AI Agent、自动报告、自动诊断、自动方案。但做出来不一定有人用。为什么？因为用户可能看不懂；可能不相信；可能不知道怎么操作；可能觉得这功能和真实工作流完全脱节。这种风险在传统产品时代就有，AI 时代被放大了——因为 AI 让"做出一个能跑的原型"变快了，但"做出一个真的有人用的产品"反而更难。所以企业越来越需要在正式开发之前做原型验证。UI 在这个环节是天然的人选。可以做的事：低保真线框；高保真可点击原型；直接用 AI 生成 HTML 原型给用户试用；组织用户走查、记录反馈；帮产品和研发提前发现这个功能用户根本不会用的问题。这件事的价值对管理者来说非常直接——它能省钱。让一个 UI 花两周做原型验证，提前发现方向不对，比让一整个研发团队花两个月做完才发现方向不对，便宜得多。所以这里有一句话送给团队：AI 时代，设计师不只是让产品更好看，而是让错误更早暴露。

路线三（基本功，简短带过）：从视觉执行者，升级为体验设计者。这条其实是老话题，AI 没出现的时候就该升级了，只是 AI 把这个紧迫感放大了。不要只问"页面好不好看"，要问：用户第一眼能不能看懂？用户知道下一步做什么吗？出错时有没有退路？信息有没有分层？不同角色看到的信息是不是应该不同？这一步是从"视觉 UI"到"产品 UX"的升级。能做到这件事的设计师在传统时代就稀缺，AI 时代不会消失。但单独靠这条不够——它是路线一和路线二的地基，没有地基就谈不上后两条。

路线四（组织能力，一句话）：从单页设计，升级为设计系统建设。AI 让出图变快，于是产品体验更容易变乱。今天一个样式，明天一个样式。公司需要有人建设设计系统——组件规范、AI 结论卡片、风险提示组件、人工确认组件、报告模板。普通 UI 交付页面，高级 UI 交付系统。这条更适合组织内已经在做基础设计的资深设计师，不适合新人入门。

路线五（我得说实话——这条更像顺手做）：从内部设计，升级为产品价值表达。很多版本会把"参与售前 PPT、客户报告、价值路径图"包装成一条独立升级路线。我必须诚实说——这条路线我认为是凑数的。不是说包装客户价值不重要，而是说：如果做这件事的人本身没有路线一到路线三的能力，那本质就是包装美工，AI 反而能替代得更彻底；如果做这件事的人已经有路线一到路线三的能力，那"对外讲清楚"是自然延伸，不需要单独立一个方向。所以这一条建议作为"顺手做"理解，不要当成独立升级方向去规划自己的职业路径。

所以管理者不要简单问：AI 来了以后，UI 还要不要？更应该问：我们有没有把 UI 用在更高价值的位置上？我给四条建议——第一，不要只让 UI 做美化，要让 UI 参与原型验证。理由前面讲过：让 UI 提前两周暴露错误，比让研发花两个月做错再返工划算得多。第二，不要让 UI 和产品经理抢职责，要明确边界。产品经理负责：做什么、为什么做、优先级是什么。UI/UX 负责：怎么让用户理解、信任、使用起来。如果你的团队里这两个角色还在为"原型该谁出"打架，那是组织设计问题，不是岗位问题。第三，不要只考核设计稿数量。要考核 UI 是否沉淀了组件、规范、可点击原型和用户反馈记录。出 10 张图不如沉淀 1 套系统。第四，遇到 AI 产品，不要只问模型能力够不够。要追问：这个 AI 结果用户看得懂吗？敢用吗？能反馈吗？能确认吗？如果你的 AI 产品做完用户不敢用，问题不一定在模型，更可能在 UI/UX 没有承担起信任设计的责任。一句话总结：AI 不是让管理者裁掉 UI 的理由，而是逼管理者重新定义 UI 的价值。裁掉只是省钱，重新分配位置才能真正放大 AI 投入的回报。

如果你是 UI，不要把"学习 AI"理解成学几个生成图片的软件。这些工具当然要会，但只学工具远远不够。真正要补的是：业务理解；用户研究；信息架构；交互逻辑；AI 交互设计（路线一的核心）；原型验证方法（路线二的核心）；设计系统；数据和流程意识。我把成长路线说得更直接一点——初级 UI：能把页面画好。中级 UI：能把流程设计清楚。高级 UI：能把复杂业务变简单。AI 时代的优秀 UI：能把 AI 能力变成用户可信任的产品体验。最后我想点名两类人——第一类：30+ 的资深 UI，但工作内容仍然以画图为主。这一类如果还不动手补 AI 交互或原型验证，时间真的不多了。AI 工具会先压缩你的执行价值，再压缩你的议价能力。第二类：愿意花一年时间认真补 AI 交互设计 + 原型验证的 UI。这是少有的红利窗口期。行业里能做的人非常少，企业的需求又在变大。如果你年龄、精力、心态都还来得及，这一年值得投入。

所以 AI 时代 UI 岗位不会简单消失，但它会重新分层。只做视觉执行的人，会越来越危险。能理解业务、设计 AI 交互、做原型验证、沉淀设计系统的人，会越来越稀缺。

未来的 UI，不应该只是"画界面的人"，而应该是——把复杂能力变成可理解体验的人。这句话听起来像鸡汤，但它的具体含义其实非常落地：你的工作产物，从设计稿，变成了用户路径、交互逻辑、AI 结论的表达规范、人工确认机制、和一整套设计系统。这些东西，AI 短期内做不出来。而做得出来的人，永远稀缺。
