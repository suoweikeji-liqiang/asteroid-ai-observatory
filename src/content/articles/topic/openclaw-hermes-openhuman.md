## 00:00 - 00:45｜开场：别急着切换，先弄清楚你到底缺什么

最近开源 Agent 圈有三个名字很容易刷到：OpenClaw、Hermes Agent，还有 OpenHuman。

如果你已经在用 Claude Code、Codex、Cursor，或者其他 AI Agent 工具，你可能会有一个很自然的问题：

这些新项目到底有什么区别？

我是不是应该试一下？

甚至，我是不是应该从现在用的工具切过去？

但如果你完全没听过它们，也没关系。

这期我不会默认你懂这些概念。我们先用几分钟把三个项目分别是什么讲清楚，再讲它们适合谁，最后再聊它们背后的行业趋势。

我想用一个更容易记住的方式概括：**养虾、养马，还是养人。**

OpenClaw 像养虾，重点是给 AI 一双手。

Hermes 像养马，重点是让 AI 会跑、会学、会复用经验。

OpenHuman 像养人，重点是让 AI 先认识你、记住你、理解你的上下文。

不过先说清楚，这只是一个帮助理解的框架，不是严格分类。

尤其是 OpenClaw 和 Hermes，它们其实有不少重叠。后面我们会专门讲。

听完这期，你至少能判断：哪个值得试，哪个暂时不用碰，哪个只是方向很大但还不一定适合你。

## 00:45 - 02:35｜先补概念：这三个项目到底是什么

我们先快速补一下背景。

OpenClaw 是一个个人 AI 助手项目。它的特点是让 AI 常驻在你的设备或者服务器上，然后通过 WhatsApp、Telegram、Slack、Discord、Signal、iMessage、飞书、微信、QQ 这些聊天入口跟你互动。

你可以简单理解成：它想把 AI 从单独的网页聊天框里放出来，接到你每天真实使用的通信工具和本地环境里。

Hermes Agent 是一个强调自我改进的 Agent 项目。它关注的是 Agent 怎么从经验里学习，怎么把做过的任务沉淀成 skills，也就是技能。

你可以简单理解成：它想让 Agent 不要每次都从零开始，而是能把成功经验变成下次可复用的工作手册。

OpenHuman 则是一个更偏长期记忆和个人上下文的项目。它想连接邮件、聊天、文档、代码库、日程和各种集成，把这些资料整理成一个可以给 AI 使用的记忆底座。

你可以简单理解成：它不是先问 AI 能做什么，而是先问 AI 知不知道你是谁、你在忙什么、你的资料在哪里。

所以这三个项目放在一起看，就像 Agent 的三种能力路线。

OpenClaw 更强调“怎么接入现实世界”。

Hermes 更强调“怎么越用越熟”。

OpenHuman 更强调“怎么长期理解你”。

但这里要打一个重要补丁。

OpenClaw 和 Hermes 不是两个完全互斥的东西。

它们都会涉及工具调用、任务执行、工作流和长期运行。

区别更多是切入点不同。

OpenClaw 更像从入口和 Gateway 切进去：先解决 AI 怎么被叫起来，怎么接到聊天入口和工具。

Hermes 更像从执行闭环和 skills 切进去：先解决 AI 怎么把任务跑顺，怎么把经验沉淀下来，下次少走弯路。

所以你可以把它们理解成同一类 Agent 系统的两个方向，而不是两个完全不同物种。

接下来我们一个个拆。

---

## 02:35 - 04:45｜OpenClaw：适合想把 AI 放进日常入口的人

先说 OpenClaw。

OpenClaw 解决的问题很直白：AI 不应该永远关在网页聊天框里。

你可以把它理解成一个运行在你自己设备，或者服务器上的个人 AI 助手。你不必每次打开一个 AI 网页，再复制粘贴上下文，再等它回答。

你可以在原本就在用的聊天入口里叫它，让它在你的设备、浏览器、文件、工作区里执行任务，然后把结果发回来。

所以我说它像“养虾”。

不是因为虾多聪明，而是因为它有爪子。

OpenClaw 的核心是 Gateway，可以翻译成“网关”，也可以理解成“常驻控制平面”。

前面，它接各种聊天入口。

后面，它接浏览器、文件、工具、技能和工作区。

你从微信或者 Slack 发一句话进来，Gateway 负责判断：这是哪个会话，能访问什么工具，应该交给哪个执行流程。

所以 OpenClaw 适合什么人？

第一类，是你已经有很多聊天入口，想把 AI 放进自己的日常工作流。

比如你平时就在 Slack、飞书、Telegram、微信里处理事情，不想每天打开十几个 AI 网页。

第二类，是你有自己的设备或者服务器，愿意折腾常驻服务。

因为 OpenClaw 更像是你自己养一个 AI 中控，不是一个打开网页就能用的轻量产品。

第三类，是你很在意 AI 能不能真正碰到工具。

比如查文件、跑浏览器、调用本地环境、处理一些重复任务。

当然，OpenClaw 不是只做入口，它也会涉及执行、工具和工作流。

只是它给人的第一印象和核心切入点，更像是把 AI 接到你每天真实使用的入口里。

但如果你只是偶尔问问问题、写写文本，OpenClaw 可能就有点重。

因为 AI 一旦有了手，问题也会变复杂。

权限怎么给？

会不会碰错文件？

外部网页里的内容会不会诱导它做错事？

聊天入口、工具执行、会话隔离、审计，这些都会变成你要关心的问题。

一句话总结：

**OpenClaw 更适合想把 AI 接进日常入口和真实工具的人。它不是单纯让模型更聪明，而是让 AI 更接近你的真实工作环境。**

## 04:45 - 06:55｜Hermes：适合觉得 Agent 每次都从零开始的人

第二个是 Hermes Agent。

如果说 OpenClaw 更像是从入口和 Gateway 切进去，那 Hermes 更像是从执行闭环和技能沉淀切进去。

它关心的是：AI 怎么越用越会干。

这个点对个人用户其实很重要。

你可能也有这种感觉：现在很多 Agent 第一次做任务时，看起来很聪明，但每次都像新来的实习生。

你让它配置一个项目，它查一遍文档，踩一遍坑。

你纠正它，它这次记住了。

但换个会话，下次又忘了。

你再让它做类似任务，它又从头搜索、从头解释、从头犯错。

Hermes 想解决的就是这个问题。

它强调 built-in learning loop，可以翻译成“内置学习闭环”。

说人话就是：Agent 不应该每次都从零开始，它应该把经验沉淀下来。

Hermes 的核心是 skills，也就是技能。

你可以把 skill 理解成给 Agent 看的工作手册。

不是写给人看的介绍文档，而是告诉 Agent：遇到某类任务时，应该先读什么，按什么步骤做，哪些坑不要踩，做到什么程度才算完成。

更有意思的是，Hermes 支持 agent-managed skills。

也就是说，Agent 做完一个复杂任务之后，可以把这个流程自己整理成技能。下次再遇到类似任务，不用重新摸索。

这就是我说它像“养马”。

马不是只有手，马能跑远路，能记路线，也能被训练。

但也要强调，Hermes 并不是不碰工具、不做执行。恰恰相反，它也需要工具和执行环境。

只是它的关键卖点更偏向：怎么把任务经验变成可复用能力。

那 Hermes 适合什么人？

第一类，是你经常让 Agent 做重复但不完全相同的任务。

比如维护项目、写脚本、改文档、跑测试、做数据整理。

第二类，是你希望 Agent 能逐渐适应你的工作方式。

比如你有固定的代码风格、提交习惯、检查清单、产物格式。

第三类，是你已经不满足于让 AI 回答一次，而是希望它沉淀一套可复用流程。

但如果你现在只是用 AI 临时问答，或者主要做一次性创作，Hermes 的价值可能没那么明显。

因为它真正的价值，要在重复任务里才会显现。

一句话总结：

**Hermes 更适合想让 Agent 越用越顺手的人。它不是单纯给 AI 更多入口，而是让 AI 把经验变成技能。**

## 06:55 - 09:25｜OpenHuman：适合最痛“AI 不懂我”的人

第三个是 OpenHuman。

它问的问题跟前两个不太一样。

OpenClaw 和 Hermes 虽然切入点不同，但都很关注 Agent 怎么做事。

OpenHuman 更关注的是：AI 真的认识我吗？

这其实是很多个人用户最真实的痛点。

你用 ChatGPT、Claude、Gemini 的时候，模型本身很聪明，但它不知道你的生活和工作。

它不知道你最近在做哪个项目。

不知道你邮件里发生了什么。

不知道你和别人聊过什么。

不知道你的 Notion、GitHub、日程、文档、聊天记录之间有什么关系。

所以你每次都要重新解释：我是谁，我在忙什么，这个项目背景是什么，上次我们说到哪里。

OpenHuman 想做的是，把这些东西变成一个长期记忆底座。

它的关键词是 Memory Tree，可以翻译成“记忆树”。

大概意思是：把邮件、聊天、文档、集成数据这些来源，整理成 Markdown、本地知识库、主题树、全局记忆，再给 AI 使用。

它还强调很多集成，比如 Gmail、Slack、GitHub、Notion、Calendar。

这些服务不只是临时查一下，而是可以持续成为记忆来源、触发来源、工具来源和用户画像信号。

所以我说它像“养人”。

不是说它真的变成人，而是它想让 AI 先理解你的世界，再开始帮你工作。

那 OpenHuman 适合什么人？

第一类，是你每天资料很多，邮件、聊天、文档、代码、日程到处都是。

第二类，是你经常需要 AI 帮你回忆、整理、总结、连接上下文。

第三类，是你真正想要一个长期认识你的个人 AI，而不只是临时问答工具。

但这里也要冷静。

OpenHuman 这个方向很大，但越是涉及长期记忆，越要关注隐私、权限和数据边界。

你到底愿不愿意把这么多个人数据接进去？

它现在的产品成熟度，能不能支撑你的真实工作？

这些都需要自己验证。

一句话总结：

**OpenHuman 适合最痛“AI 不懂我”的人。它不是让 AI 更会执行，而是给 AI 一个长期上下文底座。**

## 09:25 - 11:10｜到底怎么选？看你的主要矛盾是什么

现在我们把三个项目放在一起看。

如果你问：哪个更强？

这个问题其实不太对。

更好的问题是：你现在的主要矛盾是什么？

如果你缺的是入口和工具触达，那你优先看 OpenClaw。

你希望 AI 能从微信、Slack、Telegram 这些地方被叫起来，能碰到浏览器、文件和工作区，那 OpenClaw 的思路更对口。

如果你缺的是流程复用，那你优先看 Hermes。

你希望 Agent 不要每次都像新手，希望它把经验沉淀成 skill，下次少走弯路，那 Hermes 的思路更对口。

如果你缺的是长期上下文，那你优先看 OpenHuman。

你希望 AI 不要每次都忘记你是谁，不要每次都重新解释背景，那 OpenHuman 的思路更对口。

注意，我这里说的是“优先看”，不是说它们完全互斥。

OpenClaw 和 Hermes 尤其有重叠。

它们都可能涉及工具、执行、技能和工作流。

只是一个更像从入口控制出发，一个更像从执行沉淀出发。

所以你也可以用一个更简单的判断：

**你想让 AI 更容易被叫起来、够得到东西，先看 OpenClaw。**

**你想让 AI 越用越熟、下次少走弯路，先看 Hermes。**

**你想让 AI 更懂你、更懂你的长期上下文，先看 OpenHuman。**

如果你只是普通用户，我的建议是：不要急着全都切。

先从你最痛的那个点开始试。

因为这三个方向越往后，成本越高，风险也越高。

入口越多，权限越复杂。

技能越多，维护越复杂。

记忆越多，隐私越复杂。

所以选择 Agent，不是看谁概念最大，而是看它有没有解决你现在最烦的那个问题。

## 11:10 - 12:35｜升华：为什么这三个项目代表 Agent 的下一阶段

最后我们再把视角拉高一点。

为什么我觉得这三个项目值得放在一期里讲？

因为它们刚好把 Agent 的下一阶段拆开了。

过去我们很容易把 Agent 理解成“会调用工具的聊天机器人”。

但现在看，真正能长期工作的 Agent，至少需要三类能力。

第一，入口。

它要能出现在你真正工作的地方，而不是永远躲在一个网页里。

第二，技能。

它要能把做过的事情沉淀下来，不要每次都从零开始。

第三，记忆。

它要能理解你的长期上下文，而不是每次都像第一次见你。

这三个方向合起来，才像一个真正的数字助理。

有入口，它能被叫起来。

有技能，它能稳定做事。

有记忆，它知道为谁做、为什么做、之前做过什么。

再往后，还要加安全、权限、审计和成本控制。

所以这期不是告诉你马上去换工具。

恰恰相反，我想说的是：别被 Agent 新概念绕晕。

先判断它解决的是哪一层问题，再决定要不要试。

OpenClaw、Hermes、OpenHuman 共同说明了一件事：Agent 正在从一个聊天窗口，变成一个有入口、有技能、有记忆、有边界的长期系统。

这可能才是 2026 年 Agent 最值得看的变化。

## 12:35 - 13:10｜结尾：别问哪个最强，先问你要养什么

所以这期的结论很简单。

别问 OpenClaw、Hermes、OpenHuman 谁最强。

先问你自己：你到底想养什么？

如果你想让 AI 从聊天框走出来，真正接到你的工具和入口，那是养虾，OpenClaw 值得看。

如果你想让 AI 不再每次从零开始，而是把经验变成技能，那是养马，Hermes 值得看。

如果你想让 AI 长期认识你，理解你的资料、项目和上下文，那是养人，OpenHuman 值得看。

这三个方向都很有价值，但适合的人不一样，也不是完全互斥。

对个人用户来说，最重要的不是追最新概念，而是找到自己现在最痛的那一层。

你缺手，就补入口和工具。

你缺经验复用，就补技能。

你缺长期理解，就补记忆。

这才是选择 Agent 项目时最实用的判断方式。
